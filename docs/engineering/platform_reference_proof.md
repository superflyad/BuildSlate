# Platform reference and memory map proof

The `platform_reference` design-release record must point to `engineering/hardware/released/platform/platform-reference.json`. The [auditor](../../buildslate/platform_reference_proof.py) reports `missing` today because no supplier design package or selected BOM exists. A reviewed product brief or a capacity calculation cannot replace the package.

The JSON release must identify the device, revision, reviewer, and exact SHA-256 values of `selected-bom.json` and `board.bom.csv`. Its `selected_mpns` must match the selected compute, memory, and storage manufacturer part numbers. Its `topology_id`, package count, and total capacity must match the memory part's source-bound qualified topology and establish at least 128 GB. `board_refs` names the compute and storage references; the memory map and PMIC entry name their own references. Every mapped reference and MPN must appear in the released electrical BOM.

`source_bindings` records the SHA-256 values from the selected BOM's compute package drawing, reference design, and rail map; memory controller support, package drawings, and routing rules; and storage host support and pin map. The PMIC entry requires an exact manufacturer part number, board reference, active and purchasable lifecycle, and hash-bound datasheet, package drawing, and reference schematic under `engineering/hardware/released/platform/pmic/`. A source file outside that controlled directory, a planning document, or changed bytes fail the audit.

The memory map lists each active controller channel with a data width and every selected memory package with a unique board reference, channel, rank, and starting data bit. The auditor requires the package count to match the selected BOM, no channel width beyond the selected controller bus, no overlapping lanes within a rank, complete data-lane coverage for each populated channel and rank, and contiguous rank numbering. Shared lanes across different ranks are permitted only as a recorded map; supplier approval and electrical timing still require engineering review. The auditor does not infer a valid eight-package topology from the public X2 maximum or from the [CAD placement study](memory_package_fit.md).

The [hardware gate](build_to_function.md) accepts the record only if this audit passes, its revision and reviewer match the evidence record, and both the selected BOM and schematic electrical BOM are separately approved with the same bytes. Run `python -m buildslate.platform_reference_proof` to inspect the package and `python validation/validate_platform_reference_proof.py` to exercise a synthetic source-bound fixture. The fixture is a validator test, not a Slate part selection.

This proof checks internal consistency and source identity. It does not read a supplier PDF to verify its technical claim, check an actual KiCad memory pinout or routed signal integrity, certify PMIC behavior, or establish boot on hardware. The separate schematic, PCB, power, firmware, and EVT0 checks must cover those steps. The public [Hardware view](https://superflyad.github.io/BuildSlate/?tab=hardware) keeps the platform reference `missing` until the controlled release exists.
