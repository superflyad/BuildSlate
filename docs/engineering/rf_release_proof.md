# RF release proof

The [v1R RF architecture](../../engineering/rf/architecture.md) reserves four edge negotiation zones but has no selected radio, antenna, tuning network, or integrated sweep. The [RF auditor](../../buildslate/rf_proof.py) checks a future EVT0 Wi-Fi/Bluetooth design package. Cellular, UWB, and wireless charging remain disabled in this configuration.

## Controlled package

Place `rf-release.json`, `radio-parts.json`, `sweep-manifest.json`, and `coexistence.csv` under `engineering/hardware/released/rf/`. Store supplier and lab scope files under `rf/sources/` and sweep files under `rf/sweeps/`. The `rf_release` record in [hardware readiness](../../engineering/hardware/readiness.yaml) must name the release JSON with its SHA-256, revision, named reviewer, and approved disposition. The release binds its part set, sweep manifest, coexistence table, selected BOM, routed board, KiCad XML netlist, electrical BOM, mechanical assembly and manifest, generated mechanical proof, and firmware bundle by exact hashes. The readiness gate checks those upstream files against approved records.

The selected radio part set names one exact Wi-Fi/Bluetooth module and two exact antenna MPNs. The module's declared Wi-Fi generation and Bluetooth major version must meet the repository's product targets, and its host interface must appear in the selected compute platform capabilities. Its board reference and MPN must match the electrical BOM. The module's driver image must exist in the bound firmware bundle and cover the antenna role. The firmware bundle also declares a separate hardware radio-kill reference and boot, fault, update, suspend, and resume states. These are configuration checks; hardware and firmware behavior still need physical tests.

Each antenna names a supplier source, feed connector, matching components, and an ordered schematic path from the module pin to the feed pin. The auditor reads the released KiCad XML netlist and requires adjacent cross-component pins to share a net; an internal step must cross a declared matching component. Every matching reference and MPN must match the electrical BOM. The antenna MPN must match its released mechanical part. The [mechanical proof](mechanical_release_proof.md) must pass for the bound assembly and manifest, and each antenna's reported bounds must lie within its assigned [edge reservation](../../engineering/rf/keepout-map/map.yaml). Center separation must meet a source-backed requirement. Nominal connectivity and box placement do not prove controlled impedance, metal-window performance, or assembly tolerance.

## Bands and sweeps

The release names at least one market and a hash-bound lab scope. The union of market bands must equal the selected module and sweep-manifest band set. Every band has source-backed frequency edges, maximum sample step, minimum return loss, minimum antenna isolation, minimum radiation efficiency, and maximum coexistence desense. The auditor does not insert a generic global band list or regulatory limit.

For each antenna and band, the manifest requires sweeps in free space, handheld, USB-cable, and wired-charging conditions. The auditor parses the supported [Touchstone](https://ibis.org/specs/) 1.0 subset: `# MHz S RI R 50`, with strictly increasing frequencies and real/imaginary data. Two-port files use the specification's S11, S21, S12, S22 order. Each file begins with a BuildSlate comment identifying its antenna ports and condition. The parser requires each band edge, no sample gap above the source-backed step, passive magnitudes, and minimum return loss or S21 isolation across every sample. Separate CSV tables provide frequency-resolved radiation efficiency for every antenna and condition. The `coexistence.csv` table covers Wi-Fi/Bluetooth, compute-memory-storage load, USB cable, and wired charging for every selected band; its desense values must stay within the source-backed limits.

Run `python -m buildslate.rf_proof --repo-root .` to inspect the release. The [synthetic fixture](../../validation/validate_rf_proof.py) tests disconnected feeds, mismatched parts, wrong antenna placement, incomplete conditions, weak return loss, low efficiency, poor isolation, excessive desense, and stale upstream bindings. A passing design audit means the reviewed files are internally consistent with the declared thresholds. It does not establish full-wave model fidelity, radiated performance, receiver sensitivity, coexistence on hardware, RF exposure, EMC, market authorization, or a working phone. Those require the [RF validation plan](../../engineering/rf/validation-plan.md) and serialized EVT0 evidence.
