# NDA and Restricted-Data Request Checklist

Use this checklist before accepting or processing restricted supplier material.

## Authorization and handling

- [ ] User explicitly authorizes supplier contact and the proposed disclosure.
- [ ] NDA parties, scope, term, governing law, residuals, and permitted recipients are reviewed by an authorized person.
- [ ] Storage location and access controls are approved.
- [ ] Public and restricted data will not be mixed in public reports or commits.
- [ ] Export-control, geographic, and redistribution restrictions are recorded.
- [ ] Supplier document identifiers, revisions, dates, and confidentiality markings will be preserved.

## Requested engineering material

- [ ] Mechanical outline and tolerance drawing.
- [ ] Electrical limits, interfaces, reference schematic, and sequencing.
- [ ] Thermal limits, loss or power data, derating, and measurement conditions.
- [ ] Reliability, qualification, safety, and compliance evidence.
- [ ] Integration guide, reference layout, keepouts, and mounting requirements.
- [ ] Software, firmware, toolchain, evaluation hardware, and license terms.
- [ ] Sample status, production status, lifecycle, lead time, MOQ, and pricing basis.
- [ ] Change-notification and end-of-life policy.

## Repository rule

Restricted source documents must not be committed to a public repository. Commit only a permitted evidence summary that identifies the source class, review date, reviewer, supported conclusions, limitations, and any values the supplier explicitly allows to be disclosed.
